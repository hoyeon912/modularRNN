1 · DQN — the vector-state baseline

The first implementation followed the PyTorch DQN tutorial closely: a small MLP reading the environment's raw (x, ẋ, θ, θ̇) state directly, epsilon-greedy exploration, a replay buffer, and a soft-updated target network.

It was built to spec, covered by unit tests, and left at that stage — the project's requirement was a network that learns from rendered images, matching CartPole's pixel-only variant, so this vector-input model was superseded by the CNN version below before it was ever pushed to convergence. Its replay buffer, epsilon schedule, and target-update logic carried forward unchanged into every later architecture.

2 · CNN‑DQN — solved from raw pixels

A 3-layer conv stack over rendered CartPole frames (no physics state given to the network at all), stacked across timesteps so the network can infer velocity from motion. This architecture went through roughly 80 tuning runs before the mechanism that actually mattered was found.

What stalled it

  • A broken success test. The first "solved" check watched reward under the noisy training-time policy — but with a 5% exploration floor applied at every step, the odds of 500 consecutive correct actions are 0.95⁵⁰⁰ ≈ 8×10⁻¹². No amount of training could pass that test. Fixed by scoring a separate, purely-greedy evaluation rollout instead.
  • Q-value overestimation. The vanilla max bootstrap let the same network pick and score the next action, visible as TD loss climbing ~25× while reward stayed flat. Fixed with a Double-DQN target: the online network picks the action, the target network scores it.
  • An architecture-invariant ceiling. Even after both fixes, every hyperparameter and architecture combination — wider frame stacks, bigger convolutions, learning-rate schedules, exploration floors — converged to the same ~150–270 reward band. Roughly 70 configurations landed in this range with no clear route past it.
The breakthrough was n-step returns. Plain 1-step TD only propagates a reward one step back per update, so credit for a mistake several steps earlier took an enormous number of updates to arrive. Bootstrapping from 5–10 steps ahead instead let every one of eight parallel n-step runs blow past the old ceiling within a few thousand episodes — five of them reached the environment's exact maximum score.

3 · CNN‑RNN‑DQN — trading the last Linear layer for memory

Same conv front-end and Double-DQN/n-step machinery as CNN-DQN, but the final 128-unit hidden layer is an RNNCell whose hidden state persists across an entire episode instead of resetting every frame — a "stored-state" DRQN, carrying its hidden state through the replay buffer alongside each transition.

What the search found

  • It learns fast, but doesn't stay put. Every configuration reached strong reward (400+) within a few thousand episodes, then every one of them eventually showed a sharp collapse at some point — loss climbing back up right as the eval score crashed, the same moving-target signature seen in CNN-DQN before its Double-DQN fix, but not eliminated by that fix here.
  • Best-checkpoint saving became essential. Because live weights aren't guaranteed to sit at their best-ever score, train_dqn_recurrent now snapshots the policy to disk every time a greedy eval beats the previous best — so the reported result is always deployable, independent of what training does afterward.
  • Target-tracking speed reverses. CNN-DQN preferred a slow target network (τ = 0.001); the recurrent head does much better with a faster one (τ ≈ 0.01) — a slow-moving target apparently can't keep up with how quickly the hidden-state-conditioned Q-estimates shift.
  • Stability is real but seed-dependent. At the best setting, 2 of 9 independent seeds sustained near-maximum reward for the full 30,000-episode budget with no lasting collapse; the rest oscillate through good and weak stretches. No hyperparameter choice removed DQN's inherent seed sensitivity — this setting just gave it noticeably better odds than any other tested.

CNN-RNN-DQN's recurrent memory gets it to a strong policy noticeably faster than the plain CNN-DQN did in its own search — but the extra recurrent-state dynamics also introduce a real, unresolved source of instability that the feed-forward network doesn't have. For a deployment where reliability matters more than training speed, CNN-DQN's fully-solved, 5-of-8-seed result is the safer choice today; the recurrent head is the more promising direction if that instability gets run down further.
